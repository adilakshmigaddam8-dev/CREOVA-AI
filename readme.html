CREOVA AI

Discover talent. Verify creativity. Create without limits.

What it is

CREOVA connects AI creators with brands and creative agencies. It supports creator profiles and portfolios, structured campaign briefs, server-side discovery filters, deterministic brief-to-creator matching, shortlists, evidence-based verification, proposals, engagements, and versioned deliverables.

Architecture

  • UI: responsive static HTML, CSS, and vanilla JavaScript under public/. Hatchable does not run JSX/TypeScript or a front-end build step.
  • Backend: serverless API handlers in api/.
  • Database: managed PostgreSQL from migrations/0001_core.sql; demo rows are seeded by seed.sql.
  • Authentication: Hatchable passwordless email-code and passkey auth. Passwords and sessions are platform-managed.
  • Media: private object storage, randomized per-user keys, file signature/size checks, time-limited signed URLs.
  • AI: Hatchable AI SDK using GPT for structured creative-brief suggestions. OpenAI provider setup is required; the manual brief editor remains available without AI.

First-time setup

  1. Open the Hatchable project console and configure an OpenAI provider key in Setup, or enable Builder + AI in console Settings. Never add secrets to client-side files or source control.
  2. Test sign-in in a real browser and verify that email-code delivery reaches the intended inbox. Passkey support depends on browser/device.
  3. Create separate Creator and Brand / Agency accounts for the end-to-end demonstration.
  4. For admin review, have the trusted project owner promote the designated reviewer’s app_profiles role to admin through controlled database administration. Users cannot promote themselves through the profile editor.
  5. Change project visibility to Public before submitting the app to judges, if public access is expected.
  6. Supported uploads: JPEG, PNG, WebP, GIF, MP4, WebM, up to 10 MB. Upload only assets you have permission to share.

Data model

app_profiles stores the user’s app role and profile. portfolio_items stores creator-owned work and process/rights fields. briefs stores brand-owned campaigns. shortlists saves creators per brand. proposals connect creators to briefs. engagements link accepted proposals to project work. deliverables preserve submission versions and review feedback. verification_records stores claim evidence and reviewer decisions. audit_events tracks important workflow events. brief_ai_usage enforces the per-account daily AI request cap.

See the architecture diagram and API reference for route details and field summaries.

Demo walkthrough

  1. Browse the creator directory; combine query, tool, category, skill, format, availability, budget and sorting filters.
  2. Open a creator profile and portfolio; review self-reported rights and any evidence-reviewed claims.
  3. Sign in as Creator, complete the profile, create a portfolio item, and submit a verification claim with supporting evidence.
  4. Sign in separately as Brand / Agency, create a brief manually or use the AI assistant after provider setup, edit all fields, confirm budget/deadline/commercial-use/licensing, and publish.
  5. Run Find Matches, inspect the weighted scores and exclusions, and save suitable creators.
  6. Submit a creator proposal, accept it as the brand, submit a deliverable version, request a revision with feedback, submit a new version, and approve it.

Limitations

Payments/escrow and real-time chat are not implemented. Password recovery is not separate because the chosen auth is passwordless email-code/passkey. Verification is evidence review for a specific claim, not legal clearance for all use. The AI assistant is not operational until its OpenAI provider has been configured and a real generation succeeds. Email delivery, multipart upload, and the full two-account path still require manual browser checks.
