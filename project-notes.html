Architecture & substitutions

CREOVA runs on Hatchable’s native serverless architecture. The database is PostgreSQL; files are stored in private object storage and delivered using time-limited signed URLs. App end-user identity is handled by Hatchable’s passwordless email-code and passkey auth. This is not a conventional Node/Express host, so the browser UI is vanilla JavaScript rather than React/TypeScript: Hatchable does not run a JSX or TypeScript build step and does not install npm dependencies during deployment.

Browser UI (public/index.html + main.js + theme.css)
   │
   ├── Hatchable Auth (email code / passkey session)
   │
   ├── API handlers (api/*.js) ─── validation / ownership checks
   │            │
   │            ├── PostgreSQL tables (migrations/*.sql)
   │            ├── Private file storage (portfolio + deliverables)
   │            └── No-cost guided brief builder (no external model call)
   │
   └── Signed-in role views: creator / brand / app administrator

Public site visibility is controlled in Hatchable project settings; the deployment platform’s “personal” visibility is separate from the marketplace’s end-user auth.

Data model

app_profilesIdentity reference, creator/brand/admin role, biography, skills, tools, formats, budget and rights declaration.
portfolio_itemsCreator-owned work, media key/URL, tools, workflow, formats, permissions notes and visibility.
briefsBrand-owned campaign scope, deliverables, budget, deadline, commercial use, usage and licensing.
hire_requestsDirect creator commissions with project scope, budget, preferred date/time/time zone, deliverables, formats, commercial-use and licensing notes, response status, and email delivery status.
proposalsCreator application, proposed price, delivery estimate, milestones, status and duplicate prevention.
engagementsAccepted proposal links, parties, deadline, milestone progress and controlled status.
deliverablesVersioned submissions, stored file key, feedback, revision state and final approval.
verification_recordsClaim, evidence, reviewer, review notes, status and timestamp.
shortlists / audit_events / brief_ai_usageSaved creators, important lifecycle changes, and per-account daily AI request caps.

End-user ids are stored as TEXT; the platform owns passwords and sessions, so CREOVA does not create a second password table.

Environment & external setup

Brief builder: The current zero-cost guided builder turns a rough idea into editable objective, scope, content type, formats, skills, deliverables, budget and licensing fields without making an external model call. It is not represented as live generative AI; a true LLM-powered version requires an explicitly configured provider and budget.

Email authentication: Hatchable owns the email-code and passkey flow; there are no app-managed passwords or SMTP credentials in source code.

Media storage: Hatchable private object storage is used. The app stores keys and asks the server for short-lived signed URLs. Do not treat the signed URL itself as permanent.

Admin review: Admin is an app-profile role, not a project collaborator role. A trusted project owner must promote an approved reviewer through controlled database administration; users cannot choose the admin role in onboarding or edit it via profile settings.

Deploy visibility: Personal projects show the Hatchable access wall to strangers. After testing, the owner must intentionally change project visibility in Settings if judges must access the live site anonymously.

Demo fixtures & 3-minute judging script

The database contains 16 fictional demo creator profiles with 32 illustrative portfolio thumbnails across multiple categories. These are labeled as demo references, not verified client work, and do not have sign-in accounts or inboxes. They exist to make public discovery explorable without pretending sample work is independently verified.

  1. Open the marketplace and explain the creator cards, brief cards, role split, and warm editorial visual system.
  2. Open Discover creators; search a tool such as Runway and combine it with a content type, format, budget, or availability filter.
  3. Open a demo creator profile and portfolio; point out the demo-artwork label and the distinction between self-reported and evidence-reviewed rights claims.
  4. From a signed-in Brand / Agency account, choose Hire creator on a profile, fill in the project scope, budget, date, time zone, deliverables and licensing requirements, then review the request in Hiring requests. Use a registered creator account to test accept/decline and email notification; demo profiles have no inbox.
  5. Sign in with an email code, choose Creator, complete the profile, create a portfolio entry, and submit a verification claim with evidence notes.
  6. Sign in with a separate email, choose Brand / Agency, draft a brief manually or try the optional AI assistant, review/edit every field, then publish.
  7. Use Find matches, compare the scored eligible creators with the explicit exclusion reasons, and save a creator to the shortlist.
  8. Submit a creator proposal, accept it in the brand account, open the engagement, submit a deliverable version, request a revision with feedback, then submit a new version and approve it.

Testing & known boundaries

Automated checks included in this build: deploy-time route/import/migration validation; API request validation; ownership-filtered SQL writes; duplicate-proposal unique index; AI output schema validation; upload MIME signature and size validation; status-transition checks; and API smoke tests performed after deployment where the platform permits.

Manual browser checks still matter: email-code delivery and passkeys require a real browser and inbox; multipart upload behavior must be exercised through the browser; admin review requires a promoted admin app profile. These should be confirmed in the actual judging environment.

Not implemented: escrow/payments, realtime chat, guaranteed email delivery on the Free plan (transactional email can be restricted by recipient allowlist), an independently certified legal-clearance process, or an automated headless end-to-end test suite. Do not pitch these as shipped.

Rights: CREOVA records creator declarations and evidence review states; it does not certify the legality of a work, a model’s terms, training data, likeness consent, music, or third-party source assets.
